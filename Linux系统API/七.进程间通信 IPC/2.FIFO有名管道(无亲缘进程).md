# Linux 有名管道（FIFO / Named Pipe）详解完整版

**有名管道（Named Pipe，通常称为 FIFO）**是 Linux 中另一种重要的进程间通信（IPC）机制。与匿名管道只能用于具有亲缘关系的进程不同，FIFO 允许**互不相关的独立进程**（无亲缘关系）之间进行数据传输。

---

## 一、 核心概念与特点

* **文件系统中的路径名**：
FIFO 在文件系统中拥有一个真实的路径名（通过 `mkfifo` 创建），文件类型为 `p`（可以通过 `ls -l` 查看）。
* **无亲缘进程通信**：
只要知道该 FIFO 的路径，任何拥有相应权限的独立进程都可以通过 `open()`、`read()` 和 `write()` 对其进行访问。
* **内核缓冲区机制**：
尽管 FIFO 在文件系统中有节点，但**它的数据依然只存在于内核缓冲区中**，并不占用实际的磁盘存储空间。
* **生命周期**：
当所有打开该 FIFO 的进程都关闭文件描述符时，**管道中的数据会被丢弃**。但 FIFO 的路径节点会一直保留在文件系统中，直到显式调用 `unlink()` 或通过命令行将其删除。
* **先进先出（FIFO）与字节流**：
与匿名管道一样，数据严格按照先进先出的顺序读取，且没有消息边界，属于无格式字节流。

---

## 二、 如何创建 FIFO 与权限注意事项

### 1. 创建方式

* **命令行创建**：可以通过 `mkfifo` 命令在文件系统中创建一个有名管道文件：
```bash
mkfifo my_fifo

```


或者使用 `mknod` 命令：
```bash
mknod my_fifo p

```


* **C 语言系统调用创建**：
在程序中使用 `mkfifo()` 函数创建：
```c
#include <sys/types.h>
#include <sys/stat.h>
#include <errno.h>

if (mkfifo("/tmp/my_fifo", 0666) == -1) {
    if (errno != EEXIST) {
        perror("mkfifo");
        exit(EXIT_FAILURE);
    }
    // 如果文件已经存在（EEXIST），可以忽略该错误，直接继续使用
}

```



### 2. `umask` 权限提醒

* 调用 `mkfifo(path, 0666)` 时，创建出的实际文件权限会受到进程当前 `umask`（文件权限掩码）的影响。
* **实际权限计算公式**：$\text{实际权限} = \text{mode} \& \sim\text{umask}$。这与普通文件调用 `open()` 时的权限设置规则完全相同。

## 三、 FIFO 的打开规则与阻塞特性

FIFO 的 `open()` 函数行为与普通文件有很大不同，理解这些**阻塞规则**是编写稳定 FIFO 程序的关键：

1. **默认阻塞规则**：
* 如果以**只读方式**（`O_RDONLY`）打开一个 FIFO，`open()` 会**阻塞**，直到有另一个进程以**只写方式**（`O_WRONLY`）打开同一个 FIFO。
* 如果以**只写方式**（`O_WRONLY`）打开一个 FIFO，`open()` 会**阻塞**，直到有另一个进程以**只读方式**（`O_RDONLY`）打开同一个 FIFO。


2. **非阻塞模式（`O_NONBLOCK`）**：
如果在 `open()` 时指定了 `O_NONBLOCK` 标志：
* 以 `O_RDONLY | O_NONBLOCK` 打开会立即成功返回，即使当前没有进程以写方式打开。
* 以 `O_WRONLY | O_NONBLOCK` 打开时，如果当前没有进程以读方式打开，`open()` 会直接出错返回 `-1`，并将 `errno` 设置为 `ENXIO`（没有对应的设备或地址）。


3. **面试冷门：`O_RDWR` 打开的特殊行为**
* 如果以**读写模式**（`O_RDWR`）打开 FIFO，`open()` **不会阻塞**。
* 内核会在进程内部维护读、写引用，自己跟自己配对，从而绕过“必须等待另一端”的逻辑。
* 尽管有些人写测试 Demo 会用这个模式来避免阻塞，但**在生产业务中不推荐使用**，因为它破坏了单向管道的经典语义，容易导致逻辑混乱。



---

## 四、 读写语义（完全继承匿名管道规则）

一旦 `open` 成功之后，FIFO 的后续读写行为、阻塞、`SIGPIPE` 以及 EOF 规则，**与匿名管道完全一致**：

* **读写端规则**：
* **全部写端关闭**：正在 `read()` 阻塞的进程会检测到文件结束符（EOF），`read()` 返回 `0`，从而可以安全地退出循环。
* **全部读端关闭**：如果还有进程尝试向管道的**写端**写入数据，内核会向该写入进程发送 `SIGPIPE` 信号，默认会导致进程异常终止。


* **缓冲区与阻塞**：
* 缓冲区满时 `write()` 阻塞；缓冲区空时 `read()` 阻塞（除非设置了 `O_NONBLOCK`）。


* **原子性与 `PIPE_BUF**`：
* 只要单次写入的数据量**不超过 `PIPE_BUF**`（在 Linux 中恒定为 **4096 字节**），内核保证该写入操作是原子（Atomic）的，多写端交错时数据不会被打断。



---

## 五、 边界场景补充

* **多进程同时打开同一个 FIFO**：
* 支持多写、多读。
* 在多写场景下，多个写进程同时向 FIFO 写入时，依然依赖 `PIPE_BUF` 限制来保证单次写入的原子性。


* **`unlink` 的时机**：
* 调用 `unlink()` 只是将文件系统中的路径名（目录项）删除。
* 如果此时已经有进程打开了该文件描述符（`fd`），这些 `fd` 仍然可以正常进行读写操作。只有当**所有**指向该 FIFO 的文件描述符都被关闭后，内核才会真正释放其占用的内核缓冲区。

## 六、 经典代码示例（写端与读端分离）

由于 FIFO 适用于无亲缘进程，通常需要编写两个独立的程序：一个负责写（Writer），一个负责读（Reader）。

### 1. 读端程序 (`reader.c`)

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>

#define FIFO_NAME "/tmp/my_fifo"

int main() {
    char buf[1024];

    // 创建有名管道，若已存在则忽略 EEXIST 错误
    if (mkfifo(FIFO_NAME, 0666) == -1) {
        if (errno != EEXIST) {
            perror("mkfifo");
            exit(EXIT_FAILURE);
        }
    }

    // 以只读方式打开 FIFO（此处会阻塞，直到有写端连接）
    int fd = open(FIFO_NAME, O_RDONLY);
    if (fd == -1) {
        perror("open reader");
        exit(EXIT_FAILURE);
    }

    printf("Waiting for data...\n");
    ssize_t n;
    while ((n = read(fd, buf, sizeof(buf))) > 0) {
        printf("Received: %s", buf);
    }

    close(fd);
    return 0;
}

```

### 2. 写端程序 (`writer.c`)

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <string.h>

#define FIFO_NAME "/tmp/my_fifo"

int main() {
    // 以只写方式打开 FIFO（此处会阻塞，直到有读端连接）
    int fd = open(FIFO_NAME, O_WRONLY);
    if (fd == -1) {
        perror("open writer");
        exit(EXIT_FAILURE);
    }

    const char *msg = "Hello from independent writer process!\n";
    write(fd, msg, strlen(msg) + 1);

    printf("Data sent successfully.\n");

    close(fd);
    return 0;
}

```

## 七、 匿名管道 vs 有名管道（对比总结）

| 特性 | 匿名管道 (`pipe`) | 有名管道 (`FIFO`) |
| --- | --- | --- |
| **持久性** | 随进程，进程退出后自动消失 | 存在于文件系统中，需显式删除 (`unlink`) |
| **进程关系** | 仅限具有亲缘关系的进程（父子、兄弟） | 可用于任意完全独立的无亲缘进程 |
| **命名方式** | 无名字（仅通过文件描述符操作） | 有路径名（通过路径进行 `open`） |
| **使用场景** | Shell 管道命令、简单的父子进程通信 | 独立后台服务进程、守护进程之间的通信 |
