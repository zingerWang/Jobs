## 推荐阅读路线

### 系统学习

1. **打好基础**：阅读 C++ 新特性讲解，学习 Linux 系统 API，理解文件、进程和通信的基本机制。
2. **掌握并发**：按 C++ 并发编程目录阅读，先跑通线程与锁的示例，再学习任务管理、内存模型和性能分析。
3. **练习设计**：从策略、适配器、外观、观察者和工厂方法入手，用设计模式理解职责与依赖。
4. **学会排障**：配合 Linux 调试实验，用断点、调用栈、线程状态和性能数据验证自己的理解。
5. **阅读框架**：沿 bRPC 的源码地图和调用路径，连接并发、内存管理、网络 I/O 与协议处理。
6. **扩展到多节点**：从分布式系统基础理论开始，再学习共识、选主、锁与事务。

### 带着问题查阅

- **数据竞争、死锁、线程生命周期**：先看 C++ 并发编程，再结合 Linux 调试实验复现。
- **进程通信、文件与网络接口**：从 Linux 系统 API 对应目录进入。
- **服务脱离终端、systemd、nohup、串口与 PTY**：阅读[守护进程与伪终端](Linux系统API/十.守护进程、伪终端/1.守护进程、伪终端.md)，区分进程管理、控制终端关系和输入输出通道。
- **代码耦合、对象职责与扩展方式**：查看 C++ 设计模式的场景和使用边界。
- **RPC 请求经过哪些组件**：沿 bRPC 的示例、调用栈和源码位置阅读。
- **一致性、选举、分布式锁、事务**：按分布式系统章节目录定位。

## 获取与使用

```bash
git clone https://github.com/zingerWang/Jobs.git
cd Jobs
```

Markdown 可使用本地编辑器预览，常规文档也可在 GitHub 阅读；提供 HTML 的专题支持本地打开。使用相对图片路径的文章，移动时需同时保留对应图片目录。

《Linux调试与性能分析》已整理为一篇 Markdown，完整实验代码和七张配图都在文内，无需另外寻找源码或图片文件。配图使用 Base64 内嵌，部分阅读器或托管页面可能不显示，需使用支持此方式的阅读器；文末同时提供文字思维树。

### 运行示例

本仓库是多个学习专题的集合，各专题有独立的环境要求和验证方式，没有统一的顶层构建命令。

| 专题 | 环境与操作入口 |
| --- | --- |
| C++ 并发编程 | 先阅读[实验环境与验证](C++并发编程/实验环境与验证.md)，再查看[验证报告](C++并发编程/验证报告.md)；不同示例使用的语言标准和平台能力不同 |
| C++ 设计模式 | Python 3.8+ 与支持 C++17 的 g++；按[专题说明](C++设计模式/README.md)运行 `run_all.py` |
| Linux 调试与性能分析 | Linux Bash、GCC、Python 3 及文中列出的调试工具；按[正文](Linux调试与性能分析学习资料/Linux调试与性能分析.md)建立 `examples/` 目录，将代码块保存为标注的文件名，再执行对应章节的编译和实验命令 |
| bRPC 与分布式系统 | 按对应文章准备源码、依赖和实验环境，执行文中的命令与示例 |

Linux 专属实验应在 Linux、Linux 虚拟机或已配置的 WSL 环境中运行。部分文章用故意崩溃、死锁或竞态演示问题，执行前先阅读实验说明和退出方法。

建议每次学习都完成一个小闭环：**提出问题 → 阅读原理 → 运行示例 → 修改条件 → 观察失败 → 记录结论**。性能结果要结合机器、编译参数和负载判断，不能直接把示例中的数字当作通用结论。

## 笔记与配图约定

写作从具体问题出发，先建立直觉，再解释机制。表述应直接、完整：术语首次出现时说明含义，交代谁做什么、为什么这样做、会产生什么结果，不让读者自行补齐关键因果关系。类比应帮助理解，不能代替原理或引入额外困惑。

教学代码直接放在文章的代码块中，并说明环境、保存方式、运行步骤、预期结果和限制；默认使用 C++11 或更高版本，依赖特定工具或语言时使用其原生形式。全仓库规范见 [AGENTS.md](AGENTS.md) 与 [CLAUDE.md](CLAUDE.md)，两份规范同步维护。

新增笔记的 Graphviz 配图采用卡片式节点、语义配色、`PingFang SC` 字体与 200 DPI；具体规范见 [AGENTS.md](AGENTS.md)。已有专题中也保留了 SVG、HTML 和 Markdown 内嵌图片等形式。

安装 Graphviz 并准备好字体后，可在 `.dot` 文件所在目录生成 PNG：

```bash
dot -Tpng -Gdpi=200 input.dot -o output.png
```

将 `input.dot` 和 `output.png` 替换为实际文件名。缺少指定字体时可能发生字体替换，生成后应检查中文显示和排版。
