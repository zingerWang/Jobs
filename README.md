# Jobs · C++ 与 Linux 后端学习笔记

从 C++ 语言与并发出发，逐步学习 Linux 系统编程、调试与性能分析、RPC 框架和分布式系统。

可以把后端学习想成搭建一座工厂：C++ 是工具，Linux 提供基础设施，并发决定如何安排工人，RPC 负责不同车间之间的通信，分布式系统则解决多个工厂如何协作、如何应对故障。本仓库把这些知识按主题整理，方便系统学习，也方便遇到问题时回查。

## 推荐阅读路线

### 系统学习

1. **打好基础**：结合 C++ 新特性导图，学习 Linux 系统 API，理解文件、进程和通信的基本机制。
2. **掌握并发**：按 C++ 并发编程目录阅读，先跑通线程与锁的示例，再学习任务管理、内存模型和性能分析。
3. **练习设计**：从策略、适配器、外观、观察者和工厂方法入手，用设计模式理解职责与依赖。
4. **学会排障**：配合 Linux 调试实验，用断点、调用栈、线程状态和性能数据验证自己的理解。
5. **阅读框架**：沿 bRPC 的源码地图和调用路径，连接并发、内存管理、网络 I/O 与协议处理。
6. **扩展到多节点**：从分布式系统基础理论开始，再学习共识、选主、锁与事务。

### 带着问题查阅

- **数据竞争、死锁、线程生命周期**：先看 C++ 并发编程，再结合 Linux 调试实验复现。
- **进程通信、文件与网络接口**：从 Linux 系统 API 对应目录进入。
- **代码耦合、对象职责与扩展方式**：查看 C++ 设计模式的场景和使用边界。
- **RPC 请求经过哪些组件**：沿 bRPC 的示例、调用栈和源码位置阅读。
- **一致性、选举、分布式锁、事务**：按分布式系统章节目录定位。

### 运行示例

本仓库是多个学习专题的集合，各专题有独立的环境要求和验证方式，没有统一的顶层构建命令。

| 专题 | 环境与操作入口 |
| --- | --- |
| C++ 并发编程 | 先阅读[实验环境与验证](C++并发编程/实验环境与验证.md)，再查看[验证报告](C++并发编程/验证报告.md)；不同示例使用的语言标准和平台能力不同 |
| C++ 设计模式 | Python 3.8+ 与支持 C++17 的 g++；按[专题说明](C++设计模式23讲/README.md)运行 `run_all.py` |
| Linux 调试与性能分析 | Linux Bash、Make、GCC 及正文列出的调试工具；按[专题说明](Linux调试与性能分析学习资料/README.md)运行 `make` 和 `make check` |
| bRPC 与分布式系统 | 按对应文章准备源码、依赖和实验环境，执行文中的命令与示例 |

Linux 专属实验应在 Linux、Linux 虚拟机或已配置的 WSL 环境中运行。部分文章用故意崩溃、死锁或竞态演示问题，执行前先阅读实验说明和退出方法。

建议每次学习都完成一个小闭环：**提出问题 → 阅读原理 → 运行示例 → 修改条件 → 观察失败 → 记录结论**。性能结果要结合机器、编译参数和负载判断，不能直接把示例中的数字当作通用结论。

## 笔记与配图约定

写作以 **类比先行 + 底层原理 + 详细不简略** 为主线，尽量包含可复现示例、失败路径、方案对比、验证方法和参考资料。分布式系统示例统一使用 C++11 或更高版本。

新增笔记的 Graphviz 配图采用卡片式节点、语义配色、`PingFang SC` 字体与 200 DPI；具体规范见 [AGENTS.md](AGENTS.md)。已有专题中也保留了 SVG、HTML 内嵌图片和 XMind 等资料格式。

安装 Graphviz 并准备好字体后，可在 `.dot` 文件所在目录生成 PNG：

```bash
dot -Tpng -Gdpi=200 input.dot -o output.png
```

将 `input.dot` 和 `output.png` 替换为实际文件名。缺少指定字体时可能发生字体替换，生成后应检查中文显示和排版。
