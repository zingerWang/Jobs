## 建议的操作顺序

1. 解压资料包或进入本文件所在目录。
2. 在 Linux 安装正文第 02 节列出的依赖。
3. 先做第 03 节空指针实验，学习 run、bt、frame、print。
4. 再做第 05 节死锁实验，学习检查全部线程和等待关系。
5. 第 07 节用三个终端分别启动服务、抓包、发送 curl 请求。
6. 第 12 节比较两种计算模式；先检查输出结果一致，再比较耗时。

有 make 和 GCC 时，可在本目录执行 `make` 编译 C 实验，执行 `make check` 检查两个修复版和 CPU 结果一致性。故意崩溃和故意死锁的程序需要按正文在 GDB 里运行，`make check` 不会启动它们。

## 常见的三个操作问题

- 不知道终端里应该在哪个目录：先用 `pwd` 和 `ls` 确认当前目录能看到 `examples/`。
- 把 `(gdb)` 复制后报错：那是提示符，只输入后面的命令。
- 移动 Markdown 后图丢失：请把正文与 `assets/` 整个目录一起移动；HTML 已经内嵌图片，单文件可读。

完整的逐步编译、调试、抓包命令均在正文对应实验中。源文件中的函数名和文中的操作保持一致。

## 本轮修订

开篇前置阅读路线；四个实验统一为六步。第 06 节补全 core、服务和容器限制，第 15 节增补调试编译与符号匹配误区，第 16 节增加推荐工具列并保留可复制的文字思维树。原六张配图与六份源码保持不变。速查小抄区分只读观察、实验命令和会干扰目标业务的采集。
