# 实验环境与验证

本系列用 C++11 建立线程与同步基础，示例根据所用接口选择 C++11、C++17 或 C++20。部分基础章节为了让线程回收更可靠而使用 C++20 jthread；这不意味着 mutex、thread_local 或 atomic 本身到 C++20 才出现。每篇顶部与 manifest.json 标明的是整份示例的最低编译标准。

## 文件布局与阅读方式

- `01-…md` 至 `46-…md`：46 篇正文。
- `examples/01.cpp` 至 `examples/46.cpp`：完整可编译示例。
- `examples/pool.hpp`：第 24—27 篇与第 29 篇共用线程池。
- `examples/async_logger.hpp`：第 46 篇日志器。
- `examples/protocol_tests.cpp`：补充的线程池排空与日志器生命周期测试。
- `examples/deep_protocols.cpp`：有界队列关闭、可复用邮箱、发布接力、SC 与 SPSC 多容量验证。
- `examples/spsc_queue.hpp`：第 41 篇与深化测试共用的 SPSC 实现。
- `深化实验与验证.md`：新增实验的同步证明、命令、断言和验证边界。
- `images/01.dot` 至 `46.dot`：Graphviz 可编辑源文件。
- `images/01.png` 至 `46.png`：正文引用的思维导图。
- `tools/verify.py`：按每篇所需标准编译并运行；每个示例独立运行目录，防止日志实验污染源码。
- `tools/render_maps.py`：重新生成全部配图。
- `tools/benchmark_notes.py`：串行收集第 45 篇不同输入规模的原始测量记录。

正文包含一句话总结、问题与类比、机制和边界、完整代码、运行结果说明、Q&A、引用，以及末尾文字树和图片。快读可先看总结、表格、代码结果与 Q&A；深入阅读应逐步推导正确性，再修改参数复现。

## Linux 环境建议

以提供完整 C++20 线程库的 GCC/libstdc++ 或 Clang/标准库组合为基础。可在 Debian/Ubuntu 环境安装工具：

```bash
sudo apt update
sudo apt install build-essential clang graphviz python3
g++ --version
```

发行版仓库中的具体版本不同；仅支持 `-std=c++20` 语法不代表标准库实现了 jthread、barrier 和 atomic wait。遇到缺失类型，检查编译器与标准库版本，而不是删除同步逻辑绕过编译。

在系列目录编译单篇：

```bash
g++ -std=c++20 -O2 -Wall -Wextra -pedantic -pthread examples/41.cpp -o demo41
./demo41
```

批量验证：

```bash
python3 tools/verify.py --compiler g++ --jobs 2
```

`build/results.json` 保留完整命令、编译诊断、退出码和输出。默认共列出 46 个文章示例和 3 个补充测试（编号 00、47、48）；可用 `--only 17`、`--only 0` 或 `--only 47` 选择目标。单个程序默认超时 30 秒。断言是验证的一部分，不要添加 `-DNDEBUG`。性能示例只验证结果正确，不断言并行一定更快。

## Windows / MSYS2 UCRT64

本次实际使用的版本与结果见验证报告。在 PowerShell 中可使用编译器绝对路径：

```powershell
$env:PATH = 'D:\msys2\ucrt64\bin;' + $env:PATH
& 'D:\msys2\ucrt64\bin\g++.exe' -std=c++20 -O2 -Wall -Wextra -pedantic -pthread -save-temps=obj examples/41.cpp -o demo41.exe
.\demo41.exe
```

若 MSYS2 安装位置不同，请替换路径。运行程序找不到 DLL 时，把同一 UCRT64 bin 目录加入当前进程 PATH；不要随意混用 MINGW64、UCRT64 和其他发行版的 DLL。本系列没有验证 MSVC 构建，不将本机 GCC 结果推广到其他工具链。

本机 MinGW 汇编器无法正确处理中文绝对临时路径，使用相对源文件路径、独立构建目录与 `-save-temps=obj` 完成构建；该选项会保留中间文件，批量脚本把它们放入 build 子目录。第 17 篇 `--retry` 可选实验在本机超时，默认成功初始化路径通过；此差异不改变标准对异常后允许重试的要求。

## 并行算法后端

第 30 篇的 `std::execution::par` 允许实现顺序执行，能编译不代表用了多个核心。某些 libstdc++ 配置使用 TBB，可能需要额外安装和 `-ltbb`。本系列验证工具使用当前环境默认后端，没有修改全局标准库配置。

## 工具检测与性能测量

第 44 篇给出 Linux Clang ThreadSanitizer 命令。当前 Windows 验证不包括 TSan、ASan 或跨架构弱内存测试，不能把“可运行目标全部通过”当作不存在任何并发问题的证明。

第 44 篇是特意构造的逻辑竞态反例：它安全地演示“全部原子操作也可超卖”，程序检查已知错误得到复现。其他章节的正常示例使用正确协议。所有性能数字只代表当前实验条件，验证报告中的单次执行不构成公开性能基准结论。

## 使用边界

示例用于解释明确的同步协议，未穷尽系统资源耗尽、硬件故障或所有第三方接口行为。线程池 shutdown/析构与日志器 close/析构都由外部拥有者串行管理；对象销毁前必须停止其他调用者。日志示例会在运行目录覆盖 `async-demo.log`，批量验证已将它放进独立 build 子目录。

规范参考以固定 C++20 工作草案 N4861 为主，避免把后续标准措辞混入 C++11—20 教程。本次资料核对日期：2026-10-14。


## 六篇工程专题与平台条件

第 08 篇默认运行全原子的逻辑竞态反例；GDB 断点命令、Linux core 流程见正文。`--hang`、`--crash` 不属于默认通过测试。第 29 篇的 `--terminate` 是显式的预期退出码 86 实验。

第 20 篇和 `examples/signal_handler.cpp` 使用 Linux/POSIX API。脚本在非 Linux 系统将它们标记为 SKIP，而不是假编译一段空实现。Linux 上安装完整 C++20 工具链后可运行 `python3 tools/verify.py --only 20 48`。本机没有可用 WSL/Linux 运行环境，未运行这两项。

补充测试编号 00 为生命周期、47 为深化协议、48 为 Linux handler。为避免沿用旧篇号的可执行文件，可显式使用新构建目录：

```bash
python3 tools/verify.py --compiler g++ --jobs 2 --build-dir build/engineering-expansion/tests
```

第 43 篇默认只测试系统分配器工作负载，使用 `-fno-builtin-malloc -fno-builtin-free` 保留分配调用；未在本机进行 jemalloc/TCMalloc 动态替换比较。第 40 篇是单读者单写者的 HP/EBR 教学模型，不是通用回收库。
