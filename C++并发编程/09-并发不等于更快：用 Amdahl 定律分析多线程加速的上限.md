## 1. 厨房再大也绕不过唯一的收银台

假设一次工作中 20% 必须串行，80% 可均匀分配。增加厨师能缩短并行部分，却不能缩短必须由同一收银台依次处理的部分。Amdahl 定律分析的正是固定工作量下这种上限，而不是所有扩容场景的万能模型。

把单线程时间归一化为 1，串行比例为 s，使用 p 个执行单元且并行部分完美分配，则 `T(p)=s+(1-s)/p`，加速比 `S(p)=1/T(p)`。当 p 趋向无穷时，上限为 `1/s`。s=0.2 时，无限核心的理想上限也只有 5 倍。

<a id="section-2"></a>

## 2. 从公式走到工程成本

真实时间可写成 `T(p)=Ts+Tp/p+To(p)`，其中 To 包含任务分割、启动、同步、队列、负载不均衡等额外成本。并行部分也未必严格按 1/p 缩小：内存带宽饱和、缓存争用和 I/O 上限都可能成为新的瓶颈。

若锁保护的关键区覆盖大部分处理，即使启动更多线程，它们也会排队；若各分区大小差异很大，最慢的分区决定最终完成时间。先减少共享修改与不均衡，可能比更换线程 API 更有价值。

本例打印的是数学模型，明确不是实际 CPU 的性能测试。以 s=0.2 计算，p=1、2、4、8 对应理想加速比约为 1、1.667、2.5、3.333。这些数可以作为检查算式的已知结果，但不能写进产品性能宣传。

<a id="section-3"></a>

## 3. 如何选择下一步优化

| 观察 | 优先行动 | 不宜直接下的结论 |
|---|---|---|
| 线程多数时间等同一锁 | 缩短或分拆临界区 | 核心数量不够 |
| CPU 满而吞吐不涨 | 检查带宽、缓存和额外工作 | 换成原子就好 |
| 分区结束时间差异大 | 动态调度或更均匀分区 | 算法无法并行 |
| 小任务并行更慢 | 合并任务或复用线程 | 多线程总是没用 |

<a id="section-4"></a>

## 4. 验证步骤

先获得同样优化级别的正确单线程基线，固定输入和输出校验；改变线程数为 1、2、4 等，记录多轮耗时、CPU 利用率与任务分布。若工作量随核心数增加，问题已转向规模扩展，需要另行定义吞吐目标，不能机械套用固定规模的结论。

## 5. 深入推导、反例与工程取舍

<!-- depth:start -->
<a id="depth-1"></a>

### 5.1 把 Amdahl 公式一步一步算出来

设单线程完成固定工作量用时 T，其中比例 s 必须串行，其余 1−s 可完美拆给 P 个处理器。串行部分仍耗时 sT，并行部分理想耗时 (1−s)T/P，于是 Tₚ=T[s+(1−s)/P]，加速比 Sₚ=T/Tₚ=1/[s+(1−s)/P]。

当 P 趋近无穷，并行项趋近 0，仍剩 sT，因此上限为 1/s。本例 s=0.2，八线程理想加速为 1/(0.2+0.8/8)=3.333…，无限线程也只能趋近 5。这里的程序是在计算模型值，不是在测量机器性能。

<a id="depth-2"></a>

### 5.2 串行比例不是代码行数的比例

一道菜的切菜步骤可能只写了一个函数调用，却占用绝大部分时间；同理，锁内代码只有两行也可能包含昂贵的分配或 I/O。s 必须来自耗时分解，不能按“20% 源码不能并行”估算。

真实模型还需要 Tₚ=sT+(1−s)T/P+H(P)，H(P) 包含任务分发、同步、负载不均和资源争用。增加线程时前一项不变，计算项减少，但 H(P) 可能迅速增加，所以实测曲线可能先下降再上升。并行效率 Eₚ=Sₚ/P；速度提升了但效率变差并不矛盾。

<a id="depth-3"></a>

### 5.3 为什么换一种工作量会得到不同结论

Amdahl 分析固定工作量：同一张图片处理得更快多少。若多核心后处理更高分辨率的图片，讨论的是扩展工作量。Gustafson 模型常写为 S≈P−s(P−1)，其中 s 按扩展后并行运行时间中的串行比例定义；不能把两个模型里不同测量口径的 s 混用。

再考虑带宽：读取 B 字节数据，内存可持续提供 β 字节/秒，单纯搬运至少需要 B/β 秒。计算可并行不代表内存能无限加速供数。对低计算密度的求和，更多线程可能只是更早触达带宽上限；此时应减少数据移动、优化布局或合并遍历。

<a id="depth-4"></a>

### 5.4 用模型决定下一次优化投向

| 实测现象 | 可检验假设 | 合理实验 |
|---|---|---|
| 一到两线程就变慢 | H 相对计算量过大 | 增大任务粒度或复用线程 |
| 前几核加速，随后平台期 | 串行段或带宽限制 | 单测串行阶段、改变工作集 |
| 核数更多反而更慢 | 争用、调度或 NUMA 成本增长 | 记录锁等待、亲和性与内存放置 |

设原串行段占 20%，即使把并行段再提速一倍，总耗时也只是从 1 降到 0.6，加速 1.667 倍。若通过架构调整将串行段减少到 5%，理想上限才变成 20 倍。先明确受限项再优化，通常比盲目替换更“高级”的同步原语更有效。第 45 篇提供固定输入、多轮交替执行的测量起点。

## 6. 完整示例与复现

源文件：[examples/09.cpp](examples/09.cpp)。在本系列目录运行以下命令；环境准备见 [实验环境](实验环境与验证.md)。

```bash
g++ -std=c++11 -O2 -Wall -Wextra -pedantic -pthread examples/09.cpp -o demo09
./demo09
```

```cpp
#include <iomanip>
#include <iostream>
#include <stdexcept>
double speedup(double serial, unsigned workers) {
    if (serial < 0 || serial > 1 || workers == 0)
        throw std::invalid_argument("invalid model parameters");
    return 1.0 / (serial + (1.0 - serial) / workers);
}
int main() {
    std::cout << std::fixed << std::setprecision(3);
    for (unsigned p : {1u, 2u, 4u, 8u, 16u})
        std::cout << "workers=" << p << " speedup=" << speedup(0.2, p) << '\n';
    std::cout << "ideal limit=" << 1.0 / 0.2 << '\n';
}
```

### 6.1 如何判断运行结果

打印 1.000、1.667、2.500、3.333、4.000，最后理想上限为 5.000。这些是模型计算值。

## 7. Q&A（常见问题与解答）

<a id="section-7-1"></a>

### 7.1 Q：串行比例是源码行数比例吗？

A：不是，它是给定工作负载下时间或关键路径中的不可并行比例，应从实际执行分析。

<a id="section-7-2"></a>

### 7.2 Q：为什么测量偶尔出现超线性加速？

A：可能涉及缓存容量、算法路径或测量误差，模型假设已经变化；先复查基线和输入规模。

<a id="section-7-3"></a>

### 7.3 Q：应该选最大线程数吗？

A：应选择满足吞吐和延迟目标、资源成本合理的点；最大线程数往往带来更多争用。
